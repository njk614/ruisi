# 睿思孪易产品指令技能包

> **设计说明**：本 Skill 负责将用户的中文或英文自然语言请求转换为孪易平台可执行指令串，并通过 Python 执行层将指令下发到场景。指令推理由加载本文档的主 Agent 完成，指令下发由 `scripts/invoke_skill.py` 完成；实体名称从本地 `references/entity_names.json` 读取，不依赖外部查询服务。

## 必须遵守的约定（最高优先级）

> **⚠️ 以下约定为最高优先级，任何情况下不得违反。**

- **基础地址**：孪易服务基础地址默认使用 `http://test.twinioc.net`；如果调用方显式传入了 `base_url`，则必须使用该地址继续拼接固定路径。
- **禁止直连接口**：禁止用 curl、HTTP 请求或任何其他方式直接调用孪易接口。
- **指令执行统一入口**：所有指令执行（A/B/C/D 系列与 E 系列）必须通过本 Skill 自身的执行脚本完成：
  ```bash
  python scripts/invoke_skill.py --token <token> [--base-url <base-url>] --query "..." --agent-output "[指令串]"
  ```
- **实体名称匹配**：所有名称类参数必须从本地配置文件 `references/entity_names.json` 中获取，不得凭空捏造实体名。
- **不臆测结果**：脚本会输出最终回复文本，读取后继续下一步，不得在未运行脚本的情况下自行推测结果。
- **匹配不上不硬推**：需要名称类参数但未匹配到有效名称时，输出"场景中没有找到匹配的信息"，不伪造指令。
- **a01 转发来源（免确认、不回传）**：当消息发送方为 `a01@im.tuguan.net`（ruisi-overall-control 部署的 Agent）时，该消息体即用户对孪易大屏的控制请求，已由 a01 完成意图分类。本 Skill 直接将其作为 `query` 走完整识别流程（识别→生成指令串→本地校验→下发），**跳过物理设备开关（B07-B10）的用户确认**，且**执行完成后不向 a01 回传任何消息**——物理大屏画面变化即为反馈。a01 转发的消息**不含 token**，复用本 Agent **预先绑定**的场景 token（未绑定则不下发，详见"token 来源约定"）。

## 触发条件

### 何时触发本 Skill

**场景交互指令（A/B/C/D 系列）：**

- 层级切换、场景复位、图层/图表控制、演示汇报。
- 告警处理（A36/A37/A38/A39 指令）。
- 对象聚焦/选中（B01/B02，含摄像头孪生体对象操作）、搜索、灯光/温控。
- 主题切换/主题生成。
- 询问场景内容、查询孪生体数据等问答类请求（D01）。
- 时间轴播放/暂停/控制（A13/A14 等指令）。

**视频监控指令（E 系列）：**

- 用户明确要求操作**视频画面本身**（切换摄像头视频流、调整视频布局、云台控制）。
- 视频筛选与显示设置、视频翻页与导航、视频轮播控制、视频排序。
- 事件/告警查看（视频面板侧）、事件轮播与筛选。
- 时间模式切换（实时/回放）、回放操作（暂停/播放/跳转/倍速）。
- 单路云台控制（左/右/上/下转、拉近/拉远）。
- 询问摄像头名称列表（E35）、指定摄像头筛选（E34）。

### 优先关键词

| 类别     | 关键词                             |
| -------- | ---------------------------------- |
| 控制动作 | `打开` `关闭` `切换` `控制` `执行` |
| 对象操作 | `聚焦` `选中` `搜索`               |
| 视频回放 | `播放` `暂停` `回放`               |
| 视频监控 | `摄像头` `视频`                    |
| 设备控制 | `灯光` `温控器` `空调`             |
| 告警     | `告警处理`                         |

典型问法示例：打开大会议室温控器、关闭大会议室照明灯开关、切换到大会议室摄像头1、聚焦环境传感器1、处理当前告警、查看大会议室摄像头1。

### 不触发的情况

- 纯闲聊、无孪易场景控制需求、也无指令执行需求的场景。
- 用户请求与视频监控 E 系列功能均不匹配时，E 系列分支应输出"您的提问超出了我能回答的范围，请输入跟视频监控相关的问题！"。

### 来源触发：a01 转发的孪易指令

当消息发送方 JID 为 `a01@im.tuguan.net` 时，无论消息体是自然语言（如"切换到楼层20并聚焦环境传感器1"）还是已成形的指令串，都视为 ruisi-overall-control（a01）转发来的、已确认归属本 Skill 的孪易控制请求：

- 直接把消息体作为 `query`，走步骤 2-8 完整流程。
- **跳过 B07-B10 物理开关确认**（确认提示发回 a01 无意义）。
- 执行后**不回传** a01，物理大屏即反馈。

## 输入参数

| 参数名       | 类型   | 必填 | 说明                                                                 |
| ------------ | ------ | ---- | -------------------------------------------------------------------- |
| token        | string | 是   | 孪易场景 token，用于指令下发请求。a01 转发来源见下方"token 来源约定" |
| query        | string | 是   | 用户自然语言问题或控制指令（中文或英文）                             |
| agent_output | string | 是   | 主 Agent 生成的指令括号串，如 `[A02：层级切换：楼层20]`              |
| base_url     | string | 否   | 孪易服务基础地址，默认 `http://test.twinioc.net`                     |
| history_user | string | 否   | 历史用户问题与历史指令内容，用于聚焦/选中场景的层级判断              |
| no_execute   | flag   | 否   | 仅生成指令与计划文本，不调用 SendInstruction（调试用）               |

**辅助数据（非命令行参数，由 Skill 内部读取）：**

| 数据源              | 说明                                                               |
| ------------------- | ------------------------------------------------------------------ |
| `entity_names.json` | 本地实体名称配置：层级、主题、孪生体分类、图层、图表、演示汇报名称 |

**token 来源约定（含 a01 转发场景）：**

- **直连用户场景**：用户先给本 Agent 发一个孪易场景 token 短码，本 Agent 将其绑定在当前会话；之后的指令复用该已绑定 token。
- **a01 转发场景（当前方案）**：a01 转发的消息体里**不含 token**。本 Agent 需**预先绑定好一个场景 token**（由运维/用户先直接给本 ar01 Agent 发送一次 token 短码完成绑定），a01 转发来的指令复用这个已绑定的 token 下发。
  > 这是当前的临时方案，token 不随 a01 消息传递；后期再调整为随消息携带或统一 token 分发。
- **未绑定 token 时**：执行脚本返回"未检测到有效场景 token，请先输入孪易场景 token 再发送指令"。因 a01 来源不回传 a01，该提示应记录在本 Agent 侧（日志/会话），并提醒运维先给 ar01 绑定 token——**不下发任何指令**。

**输入示例**：

```bash
python scripts/invoke_skill.py \
  --token "<scene-token>" \
  --query "切换到楼层20并聚焦环境传感器1" \
  --agent-output "[A02：层级切换：楼层20&B01：聚焦对象：环境传感器1]"
```

## 输出参数

执行层将最终回复以**纯文本**形式输出到 stdout，主 Agent 直接将该文本原样转发给用户（不再包裹任何 JSON 外壳）。

| 输出   | 类型 | 说明                                     |
| ------ | ---- | ---------------------------------------- |
| stdout | text | 人类可读的计划文本或提示，原样转发给用户 |

**输出的几种取值**：

- **执行计划**（指令合法并已下发）：多行纯文本
  ```
  根据最优策略，已经为您规划如下执行计划：
  1、...
  2、...
  ```
- **未匹配（场景类）**：`场景中没有找到匹配的信息`
- **未匹配（视频类）**：`视频中没有找到匹配的信息`
- **缺少 token**：`未检测到有效场景 token，请先输入孪易场景 token 再发送指令`

发送到孪易后端的 `jsonData` 字段格式保持：`instruction_order$&query$&plan_text`，其中括号内的 `&` 由执行层统一转换为 `$` 作为分隔符。

## 执行步骤

### 步骤 1：加载实体名称配置

从 `references/entity_names.json` 加载以下配置：

| 字段              | 说明                 |
| ----------------- | -------------------- |
| `levels`          | 层级名称列表         |
| `themes`          | 主题名称列表         |
| `twin_categories` | 孪生体分类及实例名称 |
| `layers`          | 图层名称列表         |
| `charts`          | 图表名称列表         |
| `presentations`   | 演示汇报名称列表     |

### 步骤 2：识别请求目标

判断用户在做哪一类事情，并确定指令系列：

- **A/B/C/D 系列（场景交互）**：场景控制、层级切换、图层/图表控制、环境控制、演示汇报、告警处理、对象聚焦/选中/搜索、灯光控制、温控、主题切换/生成、查询类问题（D01）。
- **E 系列（视频监控）**：视频筛选与显示、翻页与导航、轮播控制、视频排序、事件/告警查看、时间模式切换、回放操作、单路云台控制、摄像头名称查询（E35）、指定摄像头筛选（E34）。

### 步骤 3：匹配实体名称（从本地配置）

解析需要参数的指令时，按以下优先级确定名称类参数：

1. 当前问题中的显式信息。
2. `history_user` 中最近一次相关操作。
3. `entity_names.json` 中的可用名称列表。

**名称匹配规则**：

- 支持模糊匹配（如"会议室摄像头"可匹配"大会议室摄像头1"）。
- 支持部分匹配（如"楼层20"匹配"楼层20"）。
- 中英文名称保持配置文件中的原始形式，不强制翻译。

如果仍无法确认名称类参数，返回"场景中没有找到匹配的信息"及相关候选数据，并放入一组 `[]` 中直接输出，不伪造指令。**此条规则优先级最高。**

### 步骤 4：生成标准指令串

按下方指令库规则生成原始执行指令，格式示例：

**A/B/C/D 系列：**

- `[A03：层级切换：下一层]`
- `[A36：告警信息：当前&A38：告警信息选中]`
- `[A01：功能切换：分析&C01：主题切换：环境监测]`

**E 系列：**

- `[E08：视频：下一个视频]`
- `[E34：筛选：大会议室摄像头2&E32：单路云台：拉近]`
- `[E02：筛选：设置显示模式，3×3]`

多指令按 `&` 连接；并列操作按 `&` 拼接在同一方括号内。

> **⚠️ 无参数固定指令也必须带上语义描述**：即使是 `A03`、`A09` 这类无参数指令，也要按指令库写成完整形式（如 `A03：层级切换：下一层`、`A09：场景复位`），**不要只输出裸指令码 `[A03]`**。执行层依据 `：` 后的动作描述生成用户可见计划文本，裸指令码会导致计划文本为空。

### 步骤 5：生成用户可见计划文本

将原始指令转换为用户当前语言的计划文本时：

- 保留动作语义。
- 去掉指令编码（如 `A03`、`B02`、`C01`）。
- 保留参数值（如"下一层""大会议室摄像头1""环境监测"）。

示例：

- `A03：层级切换：下一层` → `层级切换：下一层`
- `B07：打开灯：大会议室照明灯开关` → `打开灯：大会议室照明灯开关`
- `E08：视频：下一个视频` → `视频：下一个视频`

中文最终格式：`根据最优策略，已经为您规划如下执行计划：\n1、...\n2、...`
英文最终格式：`Based on the optimal strategy, I have prepared the following execution plan:\n1、...\n2、...`

### 步骤 6：下发前本地校验

执行层在下发孪易前，用本地 `entity_names.json` 校验名称类参数是否真实存在（详见"安全与权限"）：

- 校验通过 → 进入步骤 7 下发。
- 校验未通过 → 不下发，直接把未匹配提示作为最终输出文本返回。

### 步骤 7：执行指令

**主 Agent 负责推理生成指令串，然后自己调用脚本完成执行。`--agent-output` 的值就是上一步生成的指令串。**

执行前按指令类型判断是否需要用户确认（详见"交互模式"）：

- **物理设备开关指令（B07/B08/B09/B10）**：必须先展示操作内容并等待用户确认，收到肯定答复后才调用脚本。
- **其他指令（A/C/D/E 系列及 B01-B06/B11-B14）**：直接调用脚本，无需确认。

调用示例（直接执行）：

```bash
python scripts/invoke_skill.py \
  --token "<scene-token>" \
  --query "上一层" \
  --agent-output "[A04：层级切换：上一层]"
```

> **⚠️ 严格要求**：
>
> - `--agent-output` 的值**必须**是本轮生成的实际指令括号串，禁止传入 `[instruction_order]` 等占位符。
> - `--query` 的值**必须**是用户的原始问题文本，禁止传入指令描述或带编码前缀的字符串。

### 步骤 8：返回结果

脚本将最终回复以**纯文本**形式输出到 stdout（不再包裹 JSON），主 Agent **原样转发该文本，不要修改、不要包装**。

**禁止**：

- 输出 `A09`、`A03`、`B07` 等裸编码给用户。
- 自行编写"已发送指令"、"请查看场景"等替代性描述。
- 把"开始/停止/名称"等参数留空。

## 错误处理

| 场景                                 | 处理方式                                       | 结果   |
| ------------------------------------ | ---------------------------------------------- | ------ |
| `entity_names.json` 不存在或格式错误 | 记录错误，终止执行                             | failed |
| 需要名称类参数但未匹配到有效名称     | 输出"场景中没有找到匹配的信息"，不拼接任何指令 | 不下发 |
| E 系列未找到匹配摄像头名称           | 输出 `[视频中没有找到匹配的信息]`              | 不下发 |
| `--agent-output` 缺失                | 返回错误"需要 AI 生成指令串"                   | failed |
| 指令括号串解析失败                   | 返回"指令解析失败"及原因                       | failed |
| 孪易 `SendInstruction` 接口不可达    | 返回 API 调用失败原因，保留已生成的 plan_text  | failed |
| 用户请求与视频监控 E 系列均不匹配    | 输出"您的提问超出了我能回答的范围……"           | 不下发 |

遇到上述情况时，明确指出失败原因或未匹配信息，**不返回错误的伪结果**。

- **下发前本地校验（防幻觉安全网）**：执行层在下发前用 `entity_names.json` 校验以下指令的名称类参数，匹配不上即拦截不下发：

  | A18 / A19 | `layers`                      |
  | A23 / A24 | `charts`                      |

## 交互模式

### 交互点：物理设备开关确认（确认型）

- **触发时机**：指令串中包含 B07/B08/B09/B10 任意一条时，欢迎卡片生成后、下发前。
- **触发条件**：仅物理设备开关指令需要确认；其他所有指令直接执行。
- **a01 来源豁免**：当消息发送方为 `a01@im.tuguan.net` 时，跳过本确认步骤直接下发（a01 已完成用户侧交互，确认提示发回 a01 无意义）。
- **提示语模板**：

  中文：

  ```
  即将执行：{操作描述，如"打开灯：大会议室照明灯开关"}，请确认是否执行？（是/否）
  ```

  英文：

  ```
  The following action will be executed: {action description}. Please confirm whether to proceed. (yes/no)
  ```

- **语言一致性**：中文问题下确认提示必须全中文，英文问题下必须全英文，不得中英拼接（如禁止 `打开灯：Large Meeting RoomLight Switch`）。
- **响应处理**：
  - 用户回复"是/确认/好/执行/yes/confirm/ok/execute"等肯定词 → 调用执行脚本下发。
  - 用户回复"否/取消/不/算了/no/cancel"等否定词 → 不下发，回复与当前语言一致的取消提示。

确认后调用执行脚本示例：

```bash
python scripts/invoke_skill.py \
  --token "<scene-token>" \
  --query "打开大会议室温控器" \
  --agent-output "[B09：打开温控器：大会议室温控器]"
```

## 推理规则（主 Agent 生成指令时遵循）

1. 根据用户输入内容，智能匹配并直接输出最符合指令格式的内容。
2. 若用户输入中包含多个意图，一次输出多个对应指令。
3. 对于括号中含有"其一"的选项，必须从已知选项中选择最匹配的一个。
4. 对于括号中含有"名称"的选项，从 `references/entity_names.json` 中匹配最接近的一个；如果查找后仍无匹配，拼接固定语句"场景中没有找到匹配的信息，"以及配置文件中的相关数据，用一个 `[]` 括起来直接输出，且不拼接任何指令。**优先级最高。**
5. 当用户输入"生成XXXX"、"统计XXX"、"创建XXX"、"分析XXX"时，必须识别为"C02：主题生成：XXX"。英文场景下含 `generate`、`statistics`、`create`、`analyze`、`report` 等关键词时同样识别为 C02。判断优先级：**C02（生成）> C01（切换）**；只有明确出现"切换/switch/change to"且名称与已知主题完全匹配时才走 C01。
6. 当用户输入询问类型内容时（如"有哪些XXX"），从 `entity_names.json` 的对应分类获取所有实例名称，填入 D01 指令，格式：`D01：名称1，名称2，名称3；共X个`。
7. 当用户输入跟聚焦对象/选中对象相关时，按以下三种情况严格判断：
   - **情况一**：对话开始、没有任何历史指令，**或历史指令中存在层级切换但不存在任何对象操作（B01/B02）** → 输出必须包含"A02：层级切换：（对象所在层级）"。
   - **情况二**：上一个对象操作与当前对象在同一层级，且两次对象操作之间不存在任何层级切换指令（A02/A03/A04/A05/A06）→ 只输出对象指令，不加层级切换。
   - **情况三**：上述情况二不满足时（对象不同层级，或两次对象操作之间存在过层级切换）→ 输出必须包含"A02：层级切换：（对象所在层级）"。

   > 新 token 场景：用户携带全新 token 发起对话、第一条消息即为聚焦/选中请求时，`history_user` 为空，属于情况一，**必须**在对象指令前输出层级切换。

8. 当用户输入跟主题切换相关时，如主题名称存在，输出必须包含"A01：功能切换：分析&C01：主题切换：（主题名称）"。
9. 当用户输入跟告警相关时：
   - 看一下告警信息 → `A36：告警信息：当前`
   - 看一下最新的告警 → `A36：告警信息：当前&A38：告警信息选中`
   - 最新的历史告警 → `A37：告警信息：历史&A38：告警信息选中`
   - 查看告警触发截图 → `A38：告警信息选中&A39：告警截图：打开`

   > 如上一个指令已包含告警信息选中，则不重复输出。

10. 打开/关闭XXX灯开关时，对象名称从 `entity_names.json` 的"智能开关"分类获取，输出"B07：打开灯：（对象名称）"或"B08：关闭灯：（对象名称）"。
11. 打开/关闭XXX温控器或XXX空调时，对象名称从"温控器"分类获取，输出"B09：打开温控器：（对象名称）"或"B10：关闭温控器：（对象名称）"。
12. 与导航路径相关时，无需查询任何数据，直接识别：
    - 去开会、去会议室、会议室在哪 → `B11：显隐路径：我要去开会`（英文 "go to meeting" 等同）
    - 打印文件、找打印机 → `B12：显隐路径：我要打印文件`（英文 "print a file" 等同）
13. "打开资产盘点"、"open asset inventory" → `B13：资产盘点：打开`，直接执行。
14. "关闭资产盘点"、"close asset inventory" → `B14：资产盘点：关闭`，直接执行。
15. E34（视频筛选）和 E35（摄像头列表）依赖摄像头名称匹配。若从"摄像头"分类找不到匹配项，输出 `[视频中没有找到匹配的信息]`，不抛错。
16. "查看XXX摄像头"、"打开XXX视频" → `E34：筛选：{摄像头名称}`。
17. "XXX摄像头放大/拉近" → `E34：筛选：{摄像头名称}&E32：单路云台：拉近`；"XXX摄像头缩小/拉远" → `E34：筛选：{摄像头名称}&E33：单路云台：拉远`。只说"放大/缩小/左转"等不带名称时，直接输出对应单路云台指令（E28-E33）。
18. "查看XXX摄像头告警/事件" → `E34：筛选：{摄像头名称}&E12：事件：事件列表，选中`；只说"看一下告警信息"不含名称时，直接输出 `E12：事件：事件列表，选中`。
19. 询问"有哪些摄像头"、"摄像头列表" → `E35：名称：{摄像头名称列表}`。
20. 区分"上/下一页视频"（E05/E06）和"上/下一个视频"（E08/E09），不可混用。
21. 不需要输出思考过程；除物理设备开关指令（B07/B08/B09/B10）需等待用户确认外，其他情况不询问用户，直接按输出格式输出正确结果。
